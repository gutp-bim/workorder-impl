リスク・注意点

⚠ E2E: obs-analyzer の Issue 生成動作への依存
test_iot_to_wo.py は POST /ingest/iot-event 後に obs-analyzer が自動的に Issue を生成することを前提とする。 obs-analyzer がどのイベントタイプで Issue を生成するかのロジックを E2E テスト作成時に直接確認していない。 gutp:SmokeAlarm タイプを使用しているが、obs-analyzer の閾値設定によってはトリガーされない可能性がある。
⚠ test_report_escalation.py の条件分岐
Report 投入後の Issue が Open と PendingReview のどちらになるかは非同期処理のタイミングによる。 レビュー受理ステップは PendingReview の場合のみ実行（スキップ可）。 タイミング依存のためフレーキーになる可能性がある。
ℹ CONFLICTED の実際の使用シナリオ
現状 BookingStatus.CONFLICTED は schema に存在するが、API がこのステータスを返す経路は未実装。 将来の Booking 優先度制御や強制確定機能で使用予定の予約 enum 値として追加している。
